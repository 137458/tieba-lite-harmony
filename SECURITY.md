# Security Policy

## Supported Versions

Security fixes are applied to the current `main` branch. Older builds are unsupported.

## Reporting a Vulnerability

Use the repository's private vulnerability-reporting channel when it is available. If it is unavailable, contact the repository owner through a private GitHub channel before creating any public issue.

Do not include BDUSS, STOKEN, Cookie values, account data, signing material, private keys, complete authenticated URLs, or reproducible credentials in a report.

Include the affected revision, impact, minimal redacted reproduction steps, and any proposed mitigation.

## Response and Disclosure

Maintainers acknowledge reports within seven days and provide a status update within thirty days when contact is possible. Coordinate disclosure before publishing details, and allow a reasonable remediation window for confirmed vulnerabilities.
