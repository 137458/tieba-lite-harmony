# PRD：完整版吧内页面视觉与数据修正

## Problem Statement

完整版吧内页面仍有四项影响使用的问题：Tab 条背景全宽而内容区域显得突兀；已关注吧的等级经验数据在零分和签到/关注后的场景中不会可靠更新；帖子卡片只在服务端下发热评链时显示楼中楼预览，且异步解码会丢失子回复；右下角 FAB 胶囊没有与顶部一致的底部渐变模糊层次。

## Solution

保留现有 HDS 页面架构，按原 Android 应用的数据语义和 HarmonyOS 官方组件能力完成四条独立修正：

1. 将 Tab 从全宽背景的普通 Scroll + Row 调整为页面内容区域内的圆角分段选择器，保持 16vp 左右安全边距，并随列表自然滚出视口。
2. 等级接口成功返回后保留包含 0 在内的合法经验值；关注和签到成功后主动重新拉取等级信息。
3. 论坛列表的热评链预览完整保留子回复数据，并在卡片上显示主回复及最多三条楼中楼回复；接口未下发热评链时不伪造预览。
4. 保留 HDS FAB 的原生沉浸材质，在胶囊内侧增加由底向上减弱的渐变模糊层，同时移除为手势导航栏预留的额外安全区高度。

## User Stories

1. 作为吧内页面访客，我希望 Tab 与帖子卡片使用相同的左右内容边界，以便页面层级自然且不贴边。
2. 作为吧内页面访客，我希望 Tab 随页面内容正常滚出，以便不会形成突兀的固定横条。
3. 作为已关注吧用户，我希望看到当前等级和准确的经验进度，包括经验值为 0 的合法状态。
4. 作为签到或刚关注吧的用户，我希望操作成功后本页立即更新等级经验。
5. 作为浏览有热评链帖子的用户，我希望无需进入详情页即可看到当前评论和其前几条楼中楼回复。
6. 作为浏览未带热评链数据帖子的用户，我希望页面不显示虚构的楼中楼内容。
7. 作为吧内页面访客，我希望 FAB 胶囊底部具有与顶部模糊一致的柔和白色渐变层次。
8. 作为全面屏设备用户，我希望 FAB 不因人为安全区避让而显得悬浮过高，也不在手势区增加遮罩。

## Implementation Decisions

1. Tab 继续作为帖子列表的非粘性分组头部，不启用 `StickyStyle.Header`；视觉改造只影响 Tab 容器与选中指示，不改变首页、精品和通用 Tab 的请求路由。
2. Tab 外层遵循 16vp 页面安全边距，背景不再以全宽实色横条与页面内容分离；使用已有主题资源，深色模式保持同样层次。
3. 等级经验接口返回后无条件合并 `curScore` 与 `levelupScore`；UI 只在总经验大于 0 时绘制进度，避免除零。
4. 关注和签到成功后显式刷新等级信息，不依赖只执行一次的关注状态检查。
5. 在线程模型跨 TaskPool 重建时保留 `PostInfo.subPostList`；帖子卡片仍只以列表接口实际下发的热评链为展示条件。
6. FAB 继续使用 HDS `systemMaterialEffect` 作为外层材质；底部渐变由 FAB 内部叠层实现，不叠加额外背景色、圆角或第二层系统材质。
7. FAB 固定使用页面设计间距而非系统底部避让区，符合项目不为导航手势增加遮罩或空白的规范。

## Testing Decisions

1. 使用实际登录态访问已关注吧，分别验证经验值为 0 与非零时的等级、进度文本和进度条。
2. 在同一页面完成签到和关注后验证经验数据刷新，无需重新进入页面。
3. 使用包含热评链的 FrsPage 响应验证主回复和子回复保留并渲染；使用不含热评链的响应验证不展示预览。
4. 在浅色和深色模式下人工验证 Tab 边距、滚动消失行为、FAB 的底部渐变和无额外手势区遮挡。
5. 使用项目 Hvigor 构建命令完成 ArkTS 编译验证。

## Out of Scope

1. 不为每一篇有回复的帖子额外请求楼中楼接口；服务端未在论坛列表下发热评链时不补拉，避免列表网络放大。
2. 不实现独立发帖页或改变 FAB 的功能模式语义。
3. 不恢复 Tab 吸顶行为，也不引入系统导航栏遮罩。

## Further Notes

1. 原 Android 应用的 FAB 使用系统导航栏避让，但本项目的明确视觉规则禁止该做法，因此以本项目规则为准。
2. 楼中楼预览的可见性取决于列表响应是否包含热评链；本次修复保证已下发的数据不会在异步模型重建中丢失。
