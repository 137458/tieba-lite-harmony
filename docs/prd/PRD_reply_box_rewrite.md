# PRD：帖子详情页回复输入交互重写（沉浸式 Sheet 优化）

## Problem Statement

帖子详情页（ThreadPage）当前的回复输入交互存在以下用户体验问题：

1. **系统组件感重**：bindSheet 默认的"标题栏 + 拖拽条 + 关闭按钮"三件套占用顶部约 56vp，视觉上像系统弹窗而非应用原生组件
2. **看不到原帖上下文**：楼中楼回复时 sheet 完全遮挡了下层帖子，用户不知道自己在回复哪条帖子，容易回复错楼层
3. **布局跳动**：表情面板与键盘切换时硬切换，无过渡动画，体验生硬
4. **空间利用不合理**：SheetSize.MEDIUM 在大屏设备上显得局促，输入长回复时空间不足
5. **发送按钮位置**：发送按钮位于底部工具栏右侧，与图片/表情按钮挤在一行，容易误触

## Solution

将当前 bindSheet 半模态回复框重写为沉浸式 sheet：

1. **移除系统三件套**（title/dragBar/showClose），改用自定义顶栏：关闭按钮 + 标题 + 发送按钮，视觉与应用风格统一
2. **新增原帖预览卡片**：楼中楼回复时在顶部显示原帖楼层预览（头像 + 楼层 + 用户名 + 时间 + 正文前 2 行），点击可展开/收起完整正文
3. **SheetSize 升级到 LARGE**：接近全屏，保留顶部约 80vp 空隙隐约可见原帖上下文
4. **表情面板切换动画**：animateTo 包裹状态变化，过渡平滑
5. **发送按钮移到顶栏右侧**：与微信/QQ 一致，底部工具栏精简为图片/表情/字数/原图开关
6. **沉浸模糊背景**（如 API 支持）：sheet 背景加 backgroundBlurStyle，与悬浮底栏视觉风格统一

## User Stories

1. 作为帖子详情页访客，当我点击"写评论"按钮时，希望回复框以接近全屏的尺寸弹出，保留顶部空隙隐约看到原帖上下文，以便我知道自己仍处于该帖子中
2. 作为帖子详情页访客，当我打开回复框时，希望看到一个简洁的自定义顶栏（关闭 + 标题 + 发送），而不是系统的拖拽条+关闭按钮三件套，以便视觉与应用风格统一
3. 作为楼中楼回复用户，当我点击某楼层的"回复"按钮时，希望回复框顶部显示该楼层的预览卡片（头像 + 楼层号 + 用户名 + 时间 + 正文前 2 行），以便我确认自己回复的是哪条帖子
4. 作为楼中楼回复用户，当我点击原帖预览卡片时，希望卡片展开显示完整正文，以便我引用原帖内容时查看完整上下文
5. 作为楼中楼回复用户，当我再次点击展开的原帖预览卡片时，希望卡片收起回到 2 行预览状态，以便节省输入区空间
6. 作为回帖用户，当我点击表情按钮时，希望表情面板平滑滑出（200ms 过渡动画），而不是硬切换，以便视觉过渡自然
7. 作为回帖用户，当我点击关闭表情面板时，希望面板平滑收起，而不是瞬间消失
8. 作为回帖用户，当我在输入框输入内容时，希望顶栏右侧的"发送"按钮在有内容时变为主题色，无内容时置灰，以便我直观判断是否可发送
9. 作为回帖用户，当我点击"发送"按钮时，希望按钮显示"发送中"状态禁用点击，避免重复提交
10. 作为回帖用户，当我在上传图片时，希望顶栏发送按钮位置显示"上传图片中"状态，避免我以为卡死
11. 作为回帖用户，当我选择图片后，希望图片预览面板显示在 TextArea 上方，与原帖预览卡片下方，以便我同时看到上下文和已选图片
12. 作为回帖用户，当我点击已选图片预览中的"×"按钮时，希望该图片从已选列表中移除，与现有行为一致
13. 作为回帖用户，当我在输入框获得焦点时，希望表情面板自动收起，键盘弹出，避免两者同时显示
14. 作为回帖用户，当我点击表情按钮时，希望键盘自动收起，表情面板弹出，与键盘互斥
15. 作为回帖用户，当我在楼中楼回复时，希望顶栏标题显示"回复 @用户名"，普通回帖时显示"回复主题"
16. 作为回帖用户，当我发送成功时，希望 sheet 自动关闭，列表刷新显示新回复
17. 作为回帖用户，当我发送失败时，希望 sheet 保持打开，Toast 提示错误，已选图片和输入内容不清空，以便我修改后重试
18. 作为回帖用户，当我发送成功后，希望触感反馈（重震动）确认操作完成
19. 作为回帖用户，当我配置了"小尾巴"时，希望发送时自动追加小尾巴到内容末尾，与现有行为一致
20. 作为楼中楼回复用户，当我发送时，希望内容前自动加"回复 #(reply, portrait, userName) :"前缀，对齐 Android 原版
21. 作为回帖用户，当我切换原图模式开关时，希望开关在已有图片时才显示，与现有行为一致
22. 作为回帖用户，当我在多图上传时，希望原图开关始终可用，以便我随时切换上传策略
23. 作为开发者，希望保留现有 ReplyBox 的所有业务逻辑（pickImages/onSend/buildFinalContent/buildImageContent），仅重构 UI 层，避免引入新 bug
24. 作为开发者，希望 ReplyTarget 参数类扩展加入 originalPost 字段，承载原帖完整信息供预览卡片使用
25. 作为开发者，希望 SubPostsPage 也同步使用新的 ReplyBox，保持楼中楼回复体验一致

## Implementation Decisions

### 模块改动

1. **ReplyBox.ets**：UI 层完全重构，业务逻辑保留
   - 移除底部工具栏的"发送"按钮（移到顶栏）
   - 新增 `@Builder TopBar()`：关闭按钮 + 标题 + 发送按钮
   - 新增 `@Builder OriginalPostPreview()`：原帖预览卡片（楼中楼场景）
   - 表情面板切换包裹 `animateTo` 过渡动画
   - 顶部布局顺序：TopBar → OriginalPostPreview → SelectedImagesPanel → TextArea → BottomToolbar → EmojiPanel

2. **ReplyTarget 参数类扩展**：新增 `originalPost?: PostInfo` 字段，承载楼中楼回复时的原帖完整信息（头像、楼层、用户名、时间、正文 fragments）。普通回帖时该字段为 null

3. **ThreadPage.ets**：
   - `bindSheet` 配置：移除 title/dragBar/showClose，height 改为 SheetSize.LARGE，添加 backgroundColor 显式设置
   - `openReplyBox` 方法：楼中楼场景下将 post 参数完整传入 `replyTarget.originalPost`
   - 如 API 支持，添加 `blurStyle: BlurStyle.COMPONENT_REGULAR` 沉浸模糊背景

4. **SubPostsPage.ets**：同步使用新的 ReplyBox 组件，保持楼中楼回复体验一致（如果当前已使用 ReplyBox，则只需调整 bindSheet 配置）

### 接口契约

- `ReplyBox` 组件的 `@Param` 入参不变（tid/fid/forumName/postId 等），新增可选 `originalPost: PostInfo` 参数
- `onSentSuccess` / `onClose` 回调签名不变
- `ReplyTarget` 类新增 `originalPost: PostInfo | null = null` 字段（ArkTS 不支持联合类型 null，使用可选字段或空对象标记）

### 状态机

ReplyBox 新增内部状态：
- `isOriginalPostExpanded: boolean = false`：原帖预览卡片展开/收起状态，默认 false（收起显示 2 行预览）

### 视觉规范

- 顶栏：48vp 高，背景 `card_background`，底部 0.5vp divider 分隔线
- 原帖预览卡片：左右 16vp 边距，圆角 8，背景 `input_background`，padding 12vp
- 表情面板动画：duration 200ms，curve EaseInOut

### API 兼容性

- `bindSheet` 的 `blurStyle` 参数需要确认 API 23 是否支持，不支持时不添加（不影响功能，仅影响视觉）
- `SheetSize.LARGE` 是 ArkUI 标准 API，全版本支持
- `animateTo` 全版本支持

## Testing Decisions

### 测试策略

由于 HarmonyOS ArkUI 无成熟的单元测试框架，采用手动验证 + 截图对比的方式：

1. **视觉验证**：在每个改造点完成后截图对比新旧效果
2. **业务逻辑验证**：保留 `onSend` / `buildFinalContent` / `buildImageContent` 等纯函数逻辑不变，通过实际发送回帖验证端到端流程
3. **集成验证**：从点击"写评论" → sheet 弹出 → 输入内容 → 发送 → 列表刷新，完整流程手动走通

### 验证场景清单

- [ ] 普通回帖：点击"写评论" → sheet 弹出 → 顶栏显示"回复主题" → 输入 → 发送 → sheet 关闭 + 列表刷新
- [ ] 楼中楼回复：点击某楼层"回复" → sheet 弹出 → 顶栏显示"回复 @用户名" + 原帖预览卡片可见 → 输入 → 发送 → 内容前自动加楼中楼前缀
- [ ] 原帖预览展开：点击原帖预览卡片 → 卡片展开显示完整正文 → 再次点击收起
- [ ] 表情切换：点击表情按钮 → 表情面板平滑滑出 → TextArea 失焦 → 再次点击 → 表情面板平滑收起 → TextArea 获焦弹键盘
- [ ] 图片选择：点击图片按钮 → 选择图片 → 已选图片预览显示在 TextArea 上方 → 点击 × 移除图片
- [ ] 原图开关：选择图片后 → 显示原图开关 → 切换开关状态
- [ ] 发送按钮状态：空内容时置灰 → 有内容时主题色 → 发送中禁用 → 上传中显示"上传图片中"
- [ ] 发送失败：网络异常 → Toast 提示 → sheet 保持打开 → 已选图片和内容保留
- [ ] 小尾巴：发送时自动追加小尾巴到内容末尾
- [ ] SubPostsPage 楼中楼回复：在楼中楼页面点击回复 → 新 ReplyBox 体验一致

## Out of Scope

1. **悬浮底栏双胶囊方案**：本 PRD 不涉及 HdsTabs 双胶囊改造（API 23 兼容性问题已确认放弃）
2. **ReplyBox 业务逻辑重构**：保留现有 pickImages/onSend/buildFinalContent 等业务逻辑，仅改 UI 层
3. **回复列表展示样式**：本 PRD 不涉及评论列表展示样式（楼中楼折叠/作者高亮等）
4. **独立评论页拆分**：本 PRD 不拆分独立"全部评论"页面
5. **markdown/富文本支持**：保持纯文本输入 + 表情 + 图片，不引入富文本编辑

## Further Notes

### 关键约束

1. **沉浸光感一致性**：项目记忆铁律"沉浸光感组件必须检查完整渲染层级"，ReplyBox 内部禁止加 backgroundBlurStyle/backgroundColor/borderRadius（避免与外层 sheet 材质叠加形成白色内层）
2. **左右 16vp 边距**：所有控件遵循项目统一 16vp 左右安全边距规则
3. **深色模式**：新增 UI 元素（顶栏、原帖预览卡片）需在深色模式下验证视觉效果，子组件背景用 `input_background`（深色 `#2C2C2E`）而非 `background`（纯黑）避免黑色遮罩感
4. **资源字符串**：新增文案（如"上传图片中"已有）通过 `$r` 引用，不直接字面值
5. **API 23 兼容**：项目 `compatibleSdkVersion: 6.1.0(23)`，所有新增 API 需确认 API 23 支持

### 待运行时确认项

1. `bindSheet` 的 `blurStyle` 参数在 API 23 设备上的支持情况（如不支持则不添加，仅用 `backgroundColor` 显式设置）
2. `SheetSize.LARGE` 在不同设备上的实际高度比例（需在真机/模拟器验证）
