# PRD：吧内浏览、评论预览与分类设置收口

## Problem Statement

当前完整版吧内页、帖子详情页与设置中心存在一组相互关联的问题：FAB 的系统沉浸材质在按钮区域呈现出用户不需要的明暗渐变；评论预览缺少可配置能力，且逐楼层补取数据形成 N+1 请求；吧头经验进度因读取了未持久化的 portrait 字段而不发起请求；帖子排序入口隐蔽且快速切换时旧请求可能覆盖新结果；列表组头结构和部分触控拦截影响滑动连续性；更新检查只调用 GitHub 稳定版接口，无法发现预发行版；设置项仍集中在单页分组中，未形成独立分类页面。

## Solution

将设置首页改为 HDS 分类入口，并建立独立的个性化、内容、账号与其他设置页面。个性化页面新增两个彼此独立的评论预览开关，分别控制吧内帖子卡片预览和帖子详情普通回复下的楼中楼预览，确保关闭、仅吧内、仅详情、全部开启四种组合都可持久化并即时生效；默认仅开启帖子详情评论预览。其他页面新增“接收预发行版更新”开关，关闭时继续使用稳定版接口，开启时查询 Release 列表并过滤草稿后选择最新稳定版或预发行版。

完整版吧内页移除 FAB 的沉浸材质，仅保留无渐变的普通 HDS 浮动按钮视觉；经验请求改用现有登录头像标识并解除对关注列表成功匹配的错误依赖；排序改为可见菜单入口，并通过请求代次隔离防止旧响应覆盖；Tab 从 ListItemGroup 组头调整为普通列表内容，列表项触控按滚动优先原则处理。帖子详情优先消费 PbPage 内嵌楼中楼数据，统一作者回填和时间顺序；缺失预览时避免逐楼层无界补请求，并由个性化开关决定是否加载和渲染。

## User Stories

1. 作为吧内页用户，我希望 FAB 不再出现按钮区域内的白色渐变，以便视觉保持干净一致。
2. 作为用户，我希望分别控制吧内帖子预览和帖子详情评论预览，以便按自己的阅读习惯选择信息密度。
3. 作为用户，我希望两个预览开关支持全部四种组合，以便一个开关不会隐式影响另一个场景。
4. 作为用户，我希望默认只在帖子详情页普通回复下看到楼中楼预览，以便吧内列表保持简洁。
5. 作为用户，我希望设置修改后立即生效并在重启后保留，以便无需重复配置。
6. 作为已关注吧的用户，我希望吧头显示当前等级、当前经验和升级所需经验，以便了解升级进度。
7. 作为用户，我希望经验接口不因本地缺少错误字段而跳过，以便正常登录后可以稳定显示进度。
8. 作为吧内页用户，我希望有清晰可见的帖子排序入口，以便切换按回复时间或发布时间排序。
9. 作为快速切换排序的用户，我希望最终列表始终对应当前选中的排序，以便旧网络响应不会覆盖新结果。
10. 作为浏览长列表的用户，我希望 Tab 与帖子自然滚动，不再被组头语义影响，以便滑动连续。
11. 作为从评论按钮或操作区开始滑动的用户，我希望列表仍能响应滚动，以便子组件不会不必要地截断手势。
12. 作为帖子详情页用户，我希望普通回复下的楼中楼预览按回复时间显示，以便看到最新讨论。
13. 作为帖子详情页用户，我希望预览作者名称正确显示，以便不会在已有用户资料时显示匿名。
14. 作为网络较慢的用户，我希望评论预览不会为每个可见楼层同时发起额外请求，以便滑动和首屏保持流畅。
15. 作为稳定版用户，我希望默认只收到正式版更新，以便不会意外安装测试版本。
16. 作为测试用户，我希望可以主动接收 beta、rc 等预发行版更新，以便提前体验新功能。
17. 作为预发行版用户，我希望正式版发布后仍能被识别为更新，以便顺利回到稳定渠道。
18. 作为设置页用户，我希望设置首页只展示分类入口，以便快速理解信息架构。
19. 作为设置页用户，我希望进入“个性化”后只看到个性化设置，以便不在长单页中查找。
20. 作为设置页用户，我希望内容、账号、其他设置也各有独立页面，以便分类行为一致。
21. 作为深色模式用户，我希望所有新页面沿用 HDS、顶部 COMMON_BLUR 与资源颜色，以便深浅色体验一致。
22. 作为维护者，我希望新增字符串同步覆盖 base、zh_CN、en_US，以便国际化资源完整。

## Implementation Decisions

- 继续使用项目现有 preferences 封装负责磁盘持久化，AppStorageV2 负责运行时响应式状态，不引入第二套持久化框架。
- 评论预览使用两个独立布尔偏好：吧内帖子预览与帖子详情楼中楼预览；默认值分别为 false 和 true。
- 吧内帖子预览开关只控制帖子卡片下方的评论摘要，不影响帖子详情页；详情预览开关只控制普通回复下方楼中楼摘要及其补请求。
- FAB 保留 HDS IMMERSIVE systemMaterialEffect，并仅在 barFloatingStyle 配置一层系统材质；内部 Builder 保持透明，不叠加背景、模糊、圆角、阴影、lightColor 或自定义渐变。
- 经验请求使用登录态已有头像标识来源，不再读取无人写入的 portrait preferences 键；关注状态与经验请求解耦，接口成功后按当前吧名合并等级和经验字段。
- 经验进度值按服务端 current score 与 level-up score 计算，并对异常范围做边界保护；没有可靠数据时隐藏进度而非伪造数值。
- 吧内排序提供明确的可点击入口，支持按回复时间和按发布时间；每次刷新携带请求代次，只允许当前代次提交列表状态。
- Tab 作为普通列表内容参与滚动，不使用 ListItemGroup.header；保留 HDS 顶部渐变模糊采样，不新增底部遮罩。
- 对可滚动列表内的非独占操作区域使用允许父级滚动竞争的触控策略；真正点击操作仍保持原有行为。
- 楼中楼预览优先使用 PbPage with_floor/floor_rn 返回的数据，并通过顶层 user list 回填作者；两条数据路径统一按时间顺序和相同条数展示。
- 缺失内嵌预览时采用有界并发与可失效缓存，关闭详情预览后不发起补请求；不为吧内帖子列表批量请求每个帖子的 PbPage。
- 稳定更新通道继续使用 GitHub releases/latest；预发行通道查询 releases 列表，排除 draft，允许 prerelease，并使用现有语义版本比较器选择高于当前版本的最新版本。
- 设置首页改为分类导航页；分类子页统一使用 HdsNavigation、HDS 列表卡片和 ScrollEffectType.COMMON_BLUR，沿用现有导航栈与页面注册模式。
- 分类归属以功能语义为准：个性化包含视觉、布局、FAB 与评论预览偏好；内容包含图片、默认主页、完整版吧页与帖子行为；账号包含凭据、应用锁和退出；其他包含通知、缓存、更新与关于。

## Testing Decisions

- 优先在现有本地单元测试入口测试可抽取的纯行为：四种预览组合、版本比较、Release 草稿/预发行筛选、排序请求代次提交规则和经验进度边界。
- 使用模拟设置状态验证两个评论预览开关互不影响，并验证关闭详情预览时不会触发楼中楼补请求。
- 使用稳定版、beta、rc、draft 混合 Release 数据验证稳定通道与预发行通道选择结果。
- 使用乱序完成的两个排序请求验证只有最后一次选择更新列表。
- 使用已有 API 解码样本验证楼中楼作者可从顶层用户列表回填，并保持时间顺序。
- 使用 Hvigor 构建验证 ArkTS 严格语法、资源完整性和页面路由注册。
- 在真机验证 FAB 保留沉浸光感且无额外白色叠层、吧头经验、排序交互、设置分类导航、四种预览组合以及长列表连续滑动。
- 在网络请求日志中核对评论预览请求数量，确认不再随首屏带回复楼层数线性增长。

## Out of Scope

- 不新增服务端接口，不臆造贴吧协议字段。
- 不改变独立楼中楼页面的完整分页业务语义。
- 不把预发行版自动下载或静默安装纳入本次范围。
- 不重新设计整个应用导航架构，仅按现有导航模式拆分设置子页面。
- 不新增 FAB 自定义渐变、额外材质叠层、底部导航栏遮罩或系统级 pointLight 效果。
- 不承诺模拟器完整复现系统材质视觉，最终视觉以支持 HDS 的真机为准。

## Further Notes

- 当前经验进度缺失的确定根因是读取了从未写入的 portrait 键并提前返回；项目实际持久化的是 avatar。
- 当前更新检查使用 releases/latest，该 GitHub 接口不会返回 prerelease；现有版本比较器已经理解 beta/rc 后缀，可复用于新通道。
- FAB 采用官方 HdsTabs 写法：systemMaterialEffect 仅配置在 barFloatingStyle，Builder 为完全透明内容层；这样保留系统沉浸光感，同时避免人为白色背景或重复材质造成的局部渐变。
- 当前评论补偿请求按可见楼层触发，属于 N+1 性能风险；开关实现必须同时控制渲染和数据加载，不能只隐藏 UI。
